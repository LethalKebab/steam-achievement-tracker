# 写/改 Steam 成就攻略页的规则

适用范围:任何 Notion 攻略页,或本地 `*_achievements.md` 文件(如 `sultans_game_achievements.md`、`gugu_bahuang_achievements.md`)。

## 规则一:每个成就必须单独占一行 checkbox

`- [ ] **成就名**` / `- [x] **成就名**`,绝对不能:
- 把多个成就合并写在同一行(比如 `- [x] **A** / [x] **B**`)
- 把"全部已达成、比较无聊"的一整组成就写成一段不带 checkbox 的说明文字

**原因**:Notion markdown 里一行只有开头第一个 `[ ]`/`[x]` 会渲染成真正可交互的 checkbox,`/` 后面的会被转义成字面文本 `\[x\]`。而"把已解锁成就同步进 Notion 攻略页 checkbox"这个日常任务(`steam_guides_sync.gs` 的 `getUnlockedAchievements` action,见 `PROJECT_CONTEXT.md`)是靠精确匹配 `- [ ] **成就中文名**` 这样的行首文字来打勾的——合并写或者纯文字总结的内容,同步脚本根本找不到,等于白写。

2026-08-02 写歧路旅人(921570)和鬼谷八荒(1468810)攻略时踩过这个坑,169+88 个成就里好几个大段落(声望/财富/通关限定成就等分类)最初都是合并/纯文字写法,被用户发现三次才全部改完。

**同一游戏如果有两个成就 official 中文名重复**(比如鬼谷八荒的"妙手空空"对应两个不同的达成条件),要在 checkbox 的粗体名字后加后缀区分(如"·隐秘10次版"/"·通关100次版"),否则同步脚本匹配名字时会认错。

写完之后**一定要重新 fetch 页面验证 checkbox 真的落地了**,不要假设 `notion-update-page` 调用成功=内容正确——这次至少两次因为没验证就汇报"改完了",结果用户重新打开页面发现根本没变。

## 规则二:截图只贴真正有信息量的

给攻略配图前先确认这张图确实有信息量(地图位置、UI 截图、道具图标、剧情选项这类),不要为了"图文并茂"就随手贴一张"成就解锁弹窗"的截图——那种图除了标题文字本身不提供任何新信息,纯粹占地方。如果拿不准一张候选截图具体拍的是什么,就别贴,改成贴参考攻略的链接。

2026-08-02 给鬼谷八荒攻略贴了 5 张这种无意义的成就弹窗截图(来自 dvg.cn),被用户直接指出"useless"要求删除。

反过来,如果参考的原始攻略(wiki、TrueAchievements、Steam Guides 等)本身就配了地图/UI/选项截图,应该跟着配等价的图,不要图省事只写纯文字。

## 规则三:成就条目的写法(参考用户本人写的攻略,如博德之门3"成就"页 2023-09-16、NieR:Automata、光与影:33号远征队、渔帆暗涌)

这些是用户自己多年来写的真实攻略,风格和 Claude 后来代写的苏丹的游戏/歧路旅人/鬼谷八荒明显不同——更像私人笔记,不是给外人看的说明文档。写攻略时应该向这个真实风格靠拢,而不是套用更"文档化"的结构:

**单条格式**:`- [x] **成就名**<br>官方成就描述(有时保留原文,不强求翻译)<br>自己的攻略/心得`,三段都写在同一个 bullet 里用 `<br>` 换行,不单独起小标题。不管这条成就自己有没有解锁,只要有值得记录的门道就写清楚步骤——这是一份"打怎么打过的"记录,不是"还剩什么没做"的任务清单。真正没什么好说的成就(比如纯剧情推进自动解锁的)可以完全不写心得,甚至不写描述,一个成就名就够。

**没有开头元信息块**。不需要 `appid`/`共N个成就`/剧透警告/命名来源说明/参考攻略署名这些套话——用户自己的攻略几乎从不写这些,想到哪写到哪,直接进正文。（`appid` 这一行除外——这个是本项目日常同步脚本要用来匹配游戏的,必须保留,但不需要包装成"元信息块"的样子,单独一行放在最前面即可。)

**分节按游戏自身的成就分类走**(主线/支线/收集/战斗/杂项等),不需要在标题里标注"共N个,M项未完成"这种统计。

**语气是写给自己看的**,大量用"建议""亲测""经测试""总之""别忘了"这类口语化表达,关键的"千万别做错"步骤会用重复感叹号强调(比如"一定一定要选择杀死它!!!!"),不追求书面语的克制。

**长列表(全结局对照表、地图全收集点、鱼类图鉴分区)用 `<details><summary>` 折叠**,避免主列表被拉得很长,这个习惯和 Claude 代写的攻略是一致的,可以保留。

**引用海外攻略的关键操作细节时,直接原文摘录**(哪怕是英文),不用刻意翻译成中文再复述一遍——用户认为精确的原话比转译更可靠,尤其是操作时机/判定条件这类容易翻译走样的内容。

**不写结尾备注/总结段**。写完最后一个成就就结束了,不额外加"这份攻略哪里还不完整""来源是什么"这类收尾说明。
